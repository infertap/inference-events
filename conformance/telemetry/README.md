# Telemetry Compute conformance fixtures (v0)

Golden fixtures for the telemetry event model (`docs/telemetry-event-model.md`). The Rust
`infertap` agent must reproduce each fixture's `expect` given its `events`: the same record
stream, in order. infertap is the sole implementation of the model, so these files are the
contract — but the expectations are derived independently, so a passing run is two
implementations agreeing rather than one agreeing with itself.

## The contract is the record stream
The agent is a transducer: every ingested event produces exactly one classification-neutral
record — `store` (with `n_tokens`, and `parent_id` when the event carried a parent pointer;
absent, not null, otherwise), `evict`, or `clear` (a single scope-level record, `scope:
"all"`, transducing the event as said — the wire does not enumerate the cleared blocks, so
neither does the agent; per-block expansion is the aggregator's, over its residency model).
The parent pointers carry the prefix-chain structure: the aggregator reconstructs the tree
from the stream. Classification (residual dedup,
evicted-then-refetched vs cold) is an aggregator-side self-join over this stream and is not
part of the agent's contract. `records` and `record_counts` pin the stream.

The fixtures carry no `config` and no `local_summary`. Both were removed on 2026-07-27 with
the working sets: the agent holds no per-block state, so there is no approximate local view to
pin and no block-size input to give it. What a stateless transducer can still get wrong is
field mapping, absent-not-null, **identity scope**, and order — which is what these fixtures
now cover. Three of them (`same_hash_distinct_dp_ranks`, `same_hash_distinct_groups`,
`same_hash_distinct_instances`) exist specifically to pin that a block hash is an identity only
within an `Origin`: collapsing data-parallel workers or KV cache groups under a bare hash
silently erased the cross-worker duplication this crate exists to measure.

Regenerated by `tools/gen-telemetry-corpus.py`, which derives each expected record from the
documented semantics rather than by running the implementation under test.
