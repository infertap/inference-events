# Data model architecture

The wire contract has three layers: record structure, record-local semantics, and
stream semantics. JSON Lines and Parquet carry the same records.

## Schema and generated artifacts

`schema/records.schema.json` defines record kinds, fields, types, presence, and
conditional constraints. `tools/gen-schema.py` generates the Rust types, bundled
schemas, physical column catalog, and field reference. Edit the canonical schema;
do not edit generated files directly.

The generator supports a restricted JSON Schema 2020-12 profile. It accepts object
records with a required `kind` discriminator and numeric `at_ms`; scalar fields;
nullable scalars; string arrays; and endpoint arrays. Constraints use `const`, integer
bounds, required fields, `allOf`, `if`/`then`, and `not`. References name local definitions
and cannot carry sibling constraints. Extension fields remain open.

`tools/schema_profile.py` checks that JSON types, column types, presence, and Rust
representations agree. Unsupported constructs fail generation. Extending this profile
requires generator tests and runtime validation tests together.

## Validation boundaries

| Entry point | Contract |
|---|---|
| Canonical JSON Schema | Structure of known producer records, including conditional constraints. |
| `validate_producer_record` | Known record structure plus record-local ordering rules. Rejects unknown kinds. |
| `Record::decode` / `validate_record` | Known record validation; preserves future kinds with a valid common envelope. |
| `Record::to_value` | Checks caller modifications, reserved extension names, and reader record validity. |
| `validate_field` | Checks one known field for projected reads. Does not require omitted columns or enforce cross-field rules. |
| Direct Serde | Typed layout conversion. Serialization rejects reserved extension names; use the checked APIs for complete validation. |

Record-local ordering rules require `window_start_ms <= window_end_ms` and
`first_seq <= last_seq`. They supplement JSON Schema, which does not compare sibling
field values. Stream continuity, lifecycle scope, provenance, and identity resolution
remain producer and reader responsibilities, defined by the specification and corpus.

Unknown fields survive checked decoding and serialization. Optional nullable fields
use `Presence<T>` to distinguish omission from explicit null. Extensions cannot replace
known fields, including omitted optional fields or the record discriminator.

## Compatibility

Wire versions and Rust package versions are independent. Optional fields and new record
kinds require a wire minor increase. Changes to existing constraints, layouts, or meaning
require a wire major increase. The compatibility checker compares all structural rules
with the baseline; prose-only meaning changes require human review.

Generated public types remain ordinary Rust structs. Adding a public field can break
Rust struct literals even when the wire change is additive. Review package compatibility
separately before publishing.

## Conformance and reproducibility

The corpus contains independently specified expectations, captured wire inputs, and
constructed edge cases. It is not generated by the producer or reader under test.
Some generators use committed seed inputs, including identity vectors and wire captures.
`tools/check-generation.py` regenerates artifacts in a temporary directory and compares
them with the repository. Parquet comparisons require identical column types, metadata,
and values; encoder byte layout may differ across platforms.

`CONTRACT_HASH` covers file paths and raw bytes under `conformance/`, except itself.
It detects vendored corpus changes, including formatting and schema documentation changes.
It does not certify a consumer's implementation or replace compatibility review.
